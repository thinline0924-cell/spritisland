# Grimoire Compiler（仮）— 設計書 SPEC.md

魔導書構築ローグライク。Noita の魔法構築 × Vampire Survivors のオート攻撃と群がる敵 × Slay the Spire の毎回リセットされるランダムシナジー。
この文書はゲームの「正」の仕様です。実装と食い違ったら、どちらかを直して必ず一致させます（`CLAUDE.md` 参照）。

### 設計の柱
1. **永続強化なし。** 強さはそのランで拾った魔導書・ルーン・秘宝の組み合わせだけで決まる。
2. **読める構築。** どんな並びでも「何が起きるか」をコンパイルプレビューで事前に読める。驚きは「計算できるのに、想像を超える」ところから生まれる。
3. **エンジンの分離。** ルーンの解析・実行・戦闘シミュレーションは DOM や Pixi に一切依存しない純粋な TypeScript（`src/core`）。描画・音・UI は状態を読むだけ。
4. **決定論。** `src/core` の乱数はすべてシード付き。同じシードと同じ入力なら同じ展開になる。

## 1. ラン構造

```
タイトル ─▶ 初期魔導書の選択（ランダム3冊から1冊）
        ─▶ 第1幕（約7分）─▶ 調律の聖域（2ステップ）
        ─▶ 第2幕（約7分）─▶ 調律の聖域（2ステップ）
        ─▶ 第3幕（約7分）─▶ 勝利
        （HP が0になった時点で敗北。所持品はすべて失う）
```

### 1.1 幕（戦闘）
- 無限に広がるフィールド。カメラはプレイヤーを追う。
- 出現ディレクター（§10.4）が経過時間に応じて「出現予算」を増やし、敵の種類も解禁していく。
- 0:00〜3:30：通常の波（60秒ごとに精鋭1体）
- 3:30：**中ボス**（撃破すると霊銀と魔導書か秘宝）
- 3:30〜6:30：密度が上がる
- 6:30：**幕ボス**。出現中は雑魚の湧きが 40% に落ちる。撃破で幕クリア
- 各幕に1回、フィールドに**呪いの祭壇**が出現する（§8.3）。近くに2秒立つと起動する
- 幕が上がるごとに敵の HP 倍率は 1.0 / 2.4 / 5.0、攻撃力の倍率は 1.0 / 1.5 / 2.2

### 1.2 調律の聖域（幕間）
- 小さな分岐マップを2ステップ進む。各ステップでは2〜3個のノードから1つを選ぶ。種類は祭壇・鍛冶炉・商店・休息の4つ（§8）。
- 聖域にいる間は**いつでも全面的な組み替えができる**（魔導書の入れ替え、スロットの並べ替え、書庫との出し入れ、合成）。
- 出発すると次の幕が始まる。

### 1.3 勝敗とリザルト
- 勝利：第3幕のボス「虚無典」を撃破する
- 敗北：HP が0になる
- リザルト画面に表示するもの：シード、到達した幕と時間、最終構築のスナップショット（3冊の魔導書のツリー）、総ダメージの内訳（ルーン別・反応別）、最大連鎖数

## 2. 操作

| 入力 | 動作 |
|---|---|
| WASD / 矢印キー | 移動（8方向。斜めは正規化） |
| Space | 緊急回避ダッシュ（0.18秒で約130px。無敵0.25秒。クールダウン1.1秒） |

## 3. 魔導書（Grimoire）

### 3.1 ステータス

| ステータス | 意味 | コモン | レア | 伝説 |
|---|---|---|---|---|
| `slots` | スロット数 | 3–5 | 4–7 | 6–8 |
| `maxMana` | 最大マナ | 80–160 | 120–260 | 200–400 |
| `manaRegen` | 毎秒のマナ回復 | 20–40 | 30–60 | 50–90 |
| `castDelay` | 詠唱遅延（秒）＝詠唱と詠唱の間 | 0.25–0.50 | 0.15–0.40 | 0.05–0.30 |
| `recharge` | リチャージ時間（秒）＝1周読み終えた後の待ち | 0.6–1.2 | 0.4–1.0 | 0.2–0.7 |
| `capacity` | 演算容量（1回の詠唱で扱える「負荷」の上限。§4.7） | 6–9 | 8–12 | 11–16 |
| `spread` | 拡散角（度）。弾の向きがこの範囲でぶれる | 0–10 | 0–8 | 0–5 |
| `targeting` | 照準方式 | — | — | — |
| `traits` | 固有の常時効果 | 0個 | 1個 | 1〜2個 |

- 照準方式：`nearest`（最寄りの敵。70%）、`moveDir`（移動方向。15%）、`rotate`（回転掃射。毎秒180°回る。10%）、`random`（ランダムな方向。5%）。敵がいない場合、`nearest` は移動方向に撃つ。
- 名前は手続き的に作る（例：「灰燼の写本」「速記の祈祷書」「渇望せる黙示録」）。目立つステータスや特性から接頭語を選ぶ。

### 3.2 装備
- 同時に装備できるのは最大3冊（秘宝「第四の書架」で4冊）。各冊は独立した状態機械で詠唱する。
- 装備していない魔導書は「書架」に最大2冊まで保管できる。戦闘中に拾ったものは、空き枠があれば自動で装備し、なければ書架へ送る。

### 3.3 固有効果（traits）

| ID | 名前 | 効果 |
|---|---|---|
| `ricochet` | 跳弾の書 | すべての顕現に跳弾+1 |
| `frugal` | 節制の書 | マナ消費×0.5、弾速×0.7 |
| `shuffled` | 乱丁の書 | リチャージのたびにルーンの並びをシャッフルする（シード乱数）。ダメージ+25% |
| `shorthand` | 速記の書 | 詠唱遅延×0.5、演算容量-2 |
| `chorus` | 重唱の書 | 各詠唱で最初に現れる顕現が2回発動する |
| `thirst` | 渇望の書 | マナ回復×2、最大マナ×0.6 |
| `colossus` | 巨人の書 | 弾の大きさ×1.5、詠唱遅延+0.1 |
| `seeking` | 追尾の書 | すべての弾に弱いホーミング（2 rad/s） |
| `eternal` | 永劫の書 | リチャージ×0.5（生成時にスロット-1） |
| `infuse_fire` / `_thunder` / `_ice` / `_dark` | 元素の書 | 属性を持たない顕現にその属性を付与する（属性付与ルーンが優先） |
| `bloodbound` | 鮮血の書 | マナが足りないとき、足りない分を HP で払う（マナ5につき HP1） |
| `chained` | 連鎖の書 | 契機の最大発動回数+1 |
| `dashcast` | 疾駆の書 | ダッシュすると、この魔導書の次の詠唱の遅延がなくなる |

## 4. ルーンとコンパイラ（中核仕様）

### 4.1 ルーンの種類

| 種類 | 役割 |
|---|---|
| `spell`（顕現） | 実体を持つ魔法。弾、即着の連鎖雷、範囲爆発、設置陣、周回刃など |
| `modifier`（変質） | **直後の一塊**（顕現、または多重詠唱のまとまり）の性質を変える |
| `trigger`（契機） | **直前の顕現**を「運び手」にし、条件を満たしたら**直後の一塊**を運び手の座標から発動する |
| `multicast`（多重詠唱） | 直後の N 塊を同時に・拡散させて発動する |
| `curse`（呪い） | 変質の一種で、欠点と利点を併せ持つ。合成・売却はできない。外せるのは鍛冶炉だけ |

ルーンの実体（`RuneInstance`）は `{ uid, defId, tier }` を持つ。tier は 1 / 2 / 3。

### 4.2 読み取り順と1周（サイクル）
- 魔導書のスロットを左から読む。**空スロットは飛ばす**（存在しないものとして扱う）。空でないルーンを並べたものを「デッキ」と呼ぶ。
- **1回の詠唱 ＝ デッキのカーソル位置から「1塊（unit）」を構文解析して実行すること。**
- 詠唱後は `castDelay` だけ待ち、カーソル位置から次の詠唱を行う。
- カーソルがデッキの末尾に達すると1周が終わる。最後の詠唱の後は **`castDelay` と `recharge` の長い方**だけ待ち、カーソルを先頭に戻す。
- 1周は静的に（実行前に）すべてコンパイルしておく。これを `CompiledGrimoire.casts[]` とし、実行時は配列を順に使うだけにする。
  例外として、乱丁（シャッフル）はリチャージのたびに再コンパイルする。狂詠（ランダム化）は実行時に分岐する。

### 4.3 文法

```
unit    := primary ( TRIGGER unit )?            -- 契機は「直前の primary」と「直後の unit」をつなぐ（右結合）
primary := MODIFIER primary                     -- 変質（呪いを含む）は前置。直後の primary に掛かる
         | MULTICAST(n) unit × n                -- 多重詠唱は直後の n 個の unit を束ねる
         | SPELL
```

- **変質は顕現と多重詠唱に結び付き、契機よりも強く結合する。** たとえば `[追尾][火球][契機:命中][雷撃]` は「追尾する火球が命中したら、雷撃（追尾なし）」になる。
- **契機は右結合。** `[A][命中][B][消滅][C]` は `A →命中→ (B →消滅→ C)` になる。
- **多重詠唱の最後の子は、後ろに続く契機を吸収する。** `[二重][A][B][命中][C]` は `二重( A, B→命中→C )` になる。
- 多重詠唱の数 n は「塊」の数で数える。変質は数に入らない。`[二重][追尾][A][B]` は `二重( 追尾(A), B )` になる。

### 4.4 折り返し（Wrap）
- 1回の詠唱を解析している途中でデッキの末尾に達し、まだルーンが必要な場合は、**先頭に折り返して続きを読む**。
- 読めるのは、その詠唱が始まった位置より前のスロットだけ。同じ詠唱の中で同じスロットを2回読むことはない。
- 折り返して読んだルーンのマナ消費は ×1.5 になる（診断 `I401` を出す）。
- 折り返しが起きた詠唱で、その周は終わる（リチャージに入る）。
- 折り返してもルーンが足りなければ「空撃ち（fizzle）」になる。

### 4.5 構文エラーからの回復

| 状況 | 扱い | 診断 |
|---|---|---|
| primary を期待した位置に契機がある（例：先頭が契機） | その契機を無視して次を読む（マナは消費しない） | `E101` |
| 変質の後に顕現がない（末尾で、折り返しても尽きた） | 変質は効果なし（マナは消費しない）。折り返せるなら先頭の顕現に掛かる | `E102` |
| 契機の後に塊がない | 運び手だけ普通に発動する | `W201` |
| 多重詠唱の子が足りない | ある子だけで発動する | `W202` |

### 4.6 AST と実行計画（Plan）

コンパイルは次の4段階で、すべて純粋関数。

```
slots ─parse─▶ AST（表示・診断用。元のスロット番号を保持）
      ─analyze─▶ 診断・マナ・負荷・遅延
      ─lower─▶ CastPlan（実行用。変質を畳み込んで数値を確定させた純データ）
      ─estimate─▶ 推定 DPS・マナ収支
```

AST ノード：
- `spell { slot, rune }`
- `modifier { slot, rune, child }`
- `multicast { slot, rune, children[], missing }`
- `trigger { slot, rune, carrier, payload | null }`
- `fizzle { reason }`

Plan ノード：
- `emit { spellId, tier, element, params, flags, trigger?, sourceSlot }`
  `params` には damage・speed・lifetime・size・pierce・bounce・homing・spiral・split・crit・critMul などの確定値が入る。
- `group { pattern: parallel | fan | ring | cross, spread, children[] }`
- `TriggerPlan { condition, maxFires, interval?, damageMul, payload: PlanNode }`

**下げ方（lower）の規則：**
1. 魔導書の特性による暗黙の変質を最初に積む。
2. 変質ノードはスタックに積んで子へ渡す。多重詠唱の子はすべて同じスタックを継承する。
3. 契機の運び手は親のスタックを継承する。**後続（payload）は空のスタックから始める**（秘宝「継承の印」があれば継承する）。
4. 顕現では、基礎値（tier 別）に変質を**積んだ順に**適用する。加算は加算、乗算は乗算で、最後にクランプする。
5. 属性は最後に積んだ属性付与が勝つ。異なる属性が衝突したら `W203` を出す。
6. 運び手が多重詠唱のまとまりなら、契機はその中のすべての `emit` に付く（各子が個別に後続を発動する）。

### 4.7 コスト・負荷・過負荷
- **マナ消費**：その詠唱の AST に含まれるすべてのルーンのマナ（tier 別）の合計。後続（payload）のぶんも**詠唱時に前払い**する。折り返し分は ×1.5、節制の書は ×0.5。
- **HP コスト**：血詠の子孫は、マナの代わりに `マナ×0.25` の HP を払う。
- **負荷（load）**：含まれるすべてのルーンの `load` の合計。
- **過負荷（Overload）**：`load > capacity` になったとき。超過分を `excess` とすると次のようになる。
  - その詠唱の全ダメージ ×(1 + 0.1×excess)、上限 ×2.0
  - 詠唱者が `3×excess` の自傷ダメージを受ける
  - プレビューでは赤く脈動して表示し、`W301` を出す
  - 無限ループを防ぐ技術的な上限（実行時の連鎖深度8、1フレームの発動予算）とは別物。過負荷はプレイヤーが選べるリスクとして設計する
- **詠唱遅延**：`castDelay + Σ ルーン.castDelay`（その詠唱で読んだもの）。下限は 0.03 秒。
- **リチャージ**：`recharge + Σ ルーン.recharge`（デッキ全体）。下限は 0.1 秒。
- **マナ上限超過**：`manaCost > maxMana` の詠唱は永遠に撃てない。実行時は**飛ばして**次の詠唱へ進み（「詠唱失敗」の演出を出す。詠唱遅延は通常どおり掛かる）、`E103` を出す。デッドロックを防ぐため。鮮血の書なら HP で払えるので発動不能にならない。
- マナが足りない（ただし上限以下）の場合は、溜まるまでその位置で待つ。

### 4.9 推定 DPS（プレビュー用の概算）
- `emit` 1つあたりの期待ダメージは `damage × 期待命中数 × (1 + crit×(critMul-1))`。
  期待命中数は種類別に、弾が `min(1+pierce+bounce, 4)`、連鎖雷が `chains+1`、範囲（新星・爆発）が 3、設置陣・周回が「持続時間 ÷ 刻み間隔」になる。
- 契機の後続は、運び手1つにつき `min(maxFires, 期待命中数)` 回、`damageMul` を掛けて加算する。
- 1周の総ダメージ ÷ 1周の時間（最後以外の詠唱遅延の合計 + max(最後の詠唱遅延, リチャージ)）を出し、必要マナ毎秒が回復を上回る場合は `回復/必要` を掛けて落とす。
- あくまで目安。元素反応と秘宝の一部は含まない（含まれない要素はプレビューに明記する）。

### 4.10 実行時（Phase 3 以降で実装）
- `GrimoireRuntime` は `ready → casting → delay → … → recharging → ready` の状態機械。毎ティック `tick(dt, ctx)` が「発動すべき CastPlan」を返す。
- 戦闘シミュレーションは Plan を受け取り、`emit` を実体化する。契機は実体のイベント（命中・消滅・時間・撃破・跳弾・近接）に結び付ける。
- 連鎖の深度は最大8。1ティックに後続を発動できるのは 512 回まで。超えた分は次のティックへ持ち越す（性能を守るため）。
- **封印**（敵「封印術師」の能力）：指定したスロットを一時的に空として再コンパイルする。カーソルは同じ「周内の位置」を保つ。

### 6.1 属性と状態異常

| 属性 | 付与する状態 | 効果 |
|---|---|---|
| 炎 | 燃焼 | 3秒間、0.5秒ごとに元のダメージの15% |

### 6.2 元素反応（魔導書をまたいで起きる）
敵に「状態 Y」が付いているときに「属性 X」の攻撃が当たると反応が起きる。反応は元の状態を消費し、同じ敵には0.5秒の内部クールダウンがある。

| X → Y | 反応 | 効果 |
|---|---|---|
| 炎 → 冷気/凍結、氷 → 燃焼 | **蒸爆** | 半径70の爆発、dmg = 当たった攻撃×120% |
| 雷 → 冷気/凍結 | **超伝導** | 半径90の敵に「被ダメ+50%（4秒）」 |
| 炎 → 感電、雷 → 燃焼 | **誘爆** | 敵の位置で連鎖する爆発（最大3回、半径50） |
| 闇 → 燃焼/感電/冷気 | **侵蝕感染** | その状態を半径100内の敵へ広げ、持続時間を+50% |

狙うのは「A の魔導書で凍らせ、B で割る」という、3冊の役割分担。

## 7. 成長

### 7.1 マナ結晶とレベル
- 敵はマナ結晶（経験値）を落とす。吸引半径は 80px。
- 必要量 `need(L) = 5 + 4L + floor(L^1.5)`。
- レベルアップするとゲームが止まり、ルーン3つから1つを選ぶ画面が出る（§7.2）。

### 7.2 レベルアップの「1手」（Noita 型）
選んだルーンでできることは、次の**どれか1つだけ**。
1. 空きスロットに置く
2. 既存のルーンと入れ替える（外したルーンは書庫へ）
3. 同じルーンに重ねて合成する（§7.3）
4. 書庫に送る（聖域で使う）

ほかに選べること：
- **リロール**：1ランにつき3回（秘宝で増える）
- **スキップ**：HP+10 と 霊銀+5
- 置き場所にカーソルを合わせると、**置いた後のコンパイルプレビュー（差分）**が見える。編集が制限されている分、ここが判断の中心になる。

### 7.3 合成（Tier 進化）
- 同じ `defId` の2枚を重ねると、`tier = max(a, b) + 1` の1枚になる。I+I→II、II+I→III なので、III には計3枚が必要。
- Tier III にはそれ以上重ねられない。
- 呪いは合成できない。
- 自動では合成しない。「2枚のまま多重詠唱に使うか、1枚の質を上げるか」をプレイヤーが選ぶ。

### 7.4 報酬の抽選
- 種類の重み：顕現 30%、変質 40%、契機 15%、多重詠唱 15%。
- 希少度の重み（第1幕 / 第2幕 / 第3幕）：希少度1が 70/55/40、希少度2が 25/35/42、希少度3が 5/10/18。
- 1回の提示では3つとも違う `defId` にする。
- **所持バイアス**：各候補は20%の確率で「すでに持っているルーン（装備中・書庫）」から選ぶ。合成の機会を作るため。

### 7.5 書庫
- 未装備のルーンを最大12個まで保管する。あふれた場合は、捨てるものを選ぶ。

基礎値は第1幕のもの。

| ID | 名前 | HP | 速度 | 特徴（試すビルドの性質） |
|---|---|---|---|---|
| `rat` | 屍鼠 | 6 | 150 | 大群で来る。範囲攻撃が必要 |
| `ghoul` | 亡者 | 18 | 80 | 標準的な敵 |
| `archer` | 骨弓兵 | 14 | 70 | 距離を保って矢を撃つ。射程が必要 |
| `shield` | 盾持ち | 40 | 60 | 正面からの弾を防ぐ。貫通・追尾・範囲・回り込みが必要 |
| `slime` | 黒泥 | 30 | 70 | 倒すと2体に分裂する（2段階）。範囲が必要 |
| `mirror` | 鏡騎士 | 50 | 75 | 追尾の付いた弾を反射する。追尾一辺倒を罰する |
| `sealer` | 封印術師 | 35 | 60 | 220px 以内で詠唱し、魔導書のスロット1つを5秒封印する。優先して倒すべき敵 |
| `charger` | 突進獣 | 45 | 60（突進 400） | 予兆の後に直線突進する。ダッシュの腕が問われる |
| `bomber` | 爆ぜ蟲 | 10 | 130 | 近づくと自爆する |
| `wraith` | 霊体 | 25 | 90 | 2秒ごとに1秒間、実体がなくなる（すり抜ける） |
| `shaman` | 呪術師 | 30 | 65 | 周囲の敵を回復し、加速させる |
| `golem` | 石像鬼 | 160 | 45 | 重装。ランダムな1属性に耐性（-60%） |

**精鋭**は、上のどれかに接辞を1〜2個付けたもの（HP×6、大きさ×1.6、霊銀10を落とす）。
接辞：`swift`（迅速：速度×1.5）、`armored`（頑強：被ダメ -40%）、`warded`（元素結界：ランダム2属性を無効）、`splitting`（分裂：死亡時に通常個体を4体）、`manadrain`（吸魔：プレイヤーに当たると全魔導書のマナ -30）。

### 10.2 ボス（3体）
| 幕 | ID | 名前 | 行動 |
|---|---|---|---|
| 1 | `librarian` | 腐蝕の司書 | 本の眷属を召喚し、ページの弾幕を環状に撃つ。HP が半分を切ると書架を倒して直線弾を撃つ |
| 2 | `mirror_mage` | 鏡像の魔導士 | **プレイヤーの魔導書1冊目のコンパイル結果を複製して撃ち返す**（エンジンを敵にも使う）。分身を作る |
| 3 | `void_codex` | 原初の写本「虚無典」 | 3段階。①スロット封印の波 ②渦巻く弾幕＋重力場 ③画面の端から閉じていく「余白の侵蝕」 |

### 10.3 拡大縮小
- 幕による HP 倍率は §1.1。幕の中では1分ごとに HP+8%。
- 同時に存在する敵の上限は 700（超えた分の湧きは保留する）。

### 10.4 出現ディレクター
- 毎秒 `budget += base(act) × (1 + t/60 × 0.35)`。種類ごとのコストで予算を払って湧かせる。
- 出現位置は画面外のリングの上。ときどき「包囲（円形に一斉）」「奔流（片側から大群）」のパターンを混ぜる。
- 種類の解禁時刻と出現の重みは、幕ごとのデータテーブルで決める。

## 11. 戦闘シミュレーション（`src/core/sim`）

- **固定ステップ 60Hz**。描画はステップの間を補間する。ヒットストップはシミュレーションの時間倍率で表現する。
- **Object Pool**：弾・敵・地帯・ドロップは構造体配列（SoA、`Float32Array` など）か、事前に確保したオブジェクト配列で持つ。生存リストはスワップ削除で管理する。ホットループの中ではメモリを確保しない。
- **Spatial Hash Grid**：セル 64px。敵の位置を毎ティック作り直す（数え上げソートで `cellStart` / `cellItems` の型付き配列にする）。弾は自分の半径にかかるセルだけを調べる。
- 上限：弾 4,096、敵 800、地帯・設置物 256、ドロップ 2,048。パーティクルは描画側に 20,000（シミュレーション外）。
- シミュレーションは「イベント列」を出す（命中・撃破・反応・詠唱・ダメージ数値・画面シェイクの要求など）。描画と音はそれを読むだけ。

## 12. 描画と Juice（`src/render`）

- PixiJS v8。レイヤーは次の順に重ねる：床（手続き的なタイル）→ 地帯・魔法陣 → 敵 → 弾（`ParticleContainer`、加算合成）→ 軌跡 → パーティクル（加算）→ ダメージ数値（`BitmapText` のプール）。
- **テクスチャはすべて起動時に手続き的に生成する**（放射グラデーションの光の玉、幾何学的な魔法陣、ルーン文字の線画）。外部の画像は使わない。
- 発光：加算合成の光のスプライトを重ねる。品質を「高」にすると、ブルームフィルター（任意）を使う。
- 軌跡：弾ごとにリングバッファで直近の位置を持ち、細く消えていく点列またはリボンで描く。
- ヒットストップ：大きな命中（会心・反応・ボス）で 40〜80ms。
- 画面シェイク：トラウマ値方式（`shake = trauma²`、時間で減衰）。
- ダメージ数値：属性ごとに色を変え、会心は大きく、反応は名前を出す（「蒸爆！」）。近くの数値は合算してあふれを防ぐ。
- 詠唱するたびに、魔導書ごとの色の魔法陣が詠唱者の足元に一瞬開く。

## 13. サウンド（`src/audio`）

- Web Audio API による手続き的な合成のみで鳴らす。
- 出力経路：音色ごとの `GainNode` → マスターの `DynamicsCompressorNode` → 出力。
- **同時発音は最大24ボイス**。古くて小さい音から奪う。同じ種類の音は 50ms に4回まで。
- 属性ごとの音色：
  - 炎：ノイズのバースト＋ローパスの下降スイープ
  - 雷：ノコギリ波＋パチパチ音（周波数をランダムに跳ばす）＋短いノイズ
  - 氷：高いサイン波＋ FM のベル、シマー
  - 闇：低いデチューン矩形波＋フィードバックディレイ
  - 秘：三角波のプラック
- **連鎖が大きいほど**（連鎖深度・コンボ数）ピッチと明るさを上げる。反応は専用の和音を鳴らす。
- BGM：手続き的なドローンとアルペジオ（任意。後のフェーズで実装）。

## 14. UI（React + Tailwind、`src/ui`）

**実装前に静的なモックを見せて了承を得る。**

| 画面 | 内容 |
|---|---|
| タイトル | 「始める」「日替わりの儀式」「シードを入力」「設定」 |
| 初期魔導書の選択 | 3冊のカード（ステータス・特性・入っているルーン） |
| HUD | HP、レベルと結晶バー、幕と経過時間、魔導書3冊のマナバー・詠唱位置・リチャージの輪、封印の表示 |
| レベルアップ | ルーン3枚、リロール、スキップ。置き場所へのドラッグ。**差分のコンパイルプレビュー** |
| 調律の聖域 | 分岐マップ＋編集机（魔導書3冊・書架・書庫をドラッグ＆ドロップで組み替える。重ねると合成） |
| コンパイルプレビュー | 詠唱ごとのツリー（ノードとエッジで連鎖を可視化）、マナ・負荷・遅延・推定 DPS、診断の一覧（クリックすると該当スロットが光る） |

- 見た目は羊皮紙、焦げた縁、ルーン文字の装飾、セリフ体の見出し（Google Fonts の明朝系）。

## 15. 乱数とシード
- `src/core/rng.ts`：sfc32 系の PRNG。文字列のシードをハッシュして初期化する。`fork(label)` で用途別のストリーム（`world` / `loot` / `ai` / `grimoire` …）に分ける。
- 日替わりの儀式：シードは `daily-YYYY-MM-DD`。
- 描画と音の演出は `Math.random` を使ってよい（シミュレーションに影響しないため）。

## 17. テスト方針
- コンパイラ：文法の各規則、右結合、多重詠唱の吸収、変質のスコープ、折り返し、エラー回復、診断コード、マナ・負荷・遅延・リチャージ、過負荷、推定 DPS の単調性。
- 魔導書：生成の決定論（同じシードなら同じ結果）、ステータスの範囲、特性の適用、実行時の状態機械（マナ回復、待機、マナ上限超過の飛ばし）。
- 合成・報酬抽選：合成の規則、3つが重複しないこと、希少度の分布（大数での統計検定）、所持バイアス。
- アーキテクチャ：`src/core` が DOM・Pixi・React を import していないことをテストで検査する。
- シミュレーション（Phase 3 以降）：空間ハッシュと総当たりの一致、プールの確保と解放、反応の規則、同じシードでのリプレイの一致。

## 18. 性能の目標
- 弾 3,000 発、敵 600 体、パーティクル 15,000 が同時に出ている状態で、一般的なノート PC の Chrome で 60fps を保つ。
- シミュレーション1ティックは 4ms 以内（敵 600、弾 3,000）。
- 性能確認用のストレステストの場面（`?stress=1`）を用意する。
